# P0305: implicit-string-conversion

A string value crosses between `AnsiString`, `UnicodeString`, `WideString` and
`PChar` without an explicit conversion. FPC inserts a transcode or a byte
reinterpretation on your behalf.

## Failing example

```pascal
procedure Show(const Text: UnicodeString);

var
  Raw: AnsiString;
begin
  Raw := 'caf' + #$C3 + #$A9;   // UTF-8 bytes for "café"
  Show(Raw);                    // reinterpreted, not decoded
end;
```

## Fixed example

```pascal
var
  Raw: AnsiString;
begin
  Raw := 'caf' + #$C3 + #$A9;
  Show(UTF8Decode(Raw));        // the bytes become the intended text
end;
```

## Rationale

The implicit conversion reads each UTF-8 byte as one character in the system
codepage, so the output is mojibake — visible, but easy to mistake for a font
problem. It is a warning because ASCII-only or same-codepage conversions are
correct. The lint matters most at API boundaries, where the silent conversion is
also a silent performance cost.

## Silencing it

`{@allow(P0305, reason: "...")}` is legitimate when the text is known to be
ASCII or the codepage is known to match. Otherwise convert explicitly with
`UTF8Encode`/`UTF8Decode` so the transcoding site is visible.
