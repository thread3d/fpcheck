# P0505: create-without-protection

A constructor result is stored in a local and a later call in the same block can
raise, with no enclosing `try..finally`, so a failure leaks the object.

## Failing example

```pascal
Source := TFileStream.Create(Src, fmOpenRead);
Target := TFileStream.Create(Dst, fmCreate);   // raises; Source then leaks
try
  Target.CopyFrom(Source, 0);
finally
  Target.Free;
  Source.Free;
end;
```

## Fixed example

```pascal
Source := TFileStream.Create(Src, fmOpenRead);
try
  Target := TFileStream.Create(Dst, fmCreate);
  try
    Target.CopyFrom(Source, 0);
  finally
    Target.Free;
  end;
finally
  Source.Free;
end;
```

## Rationale

The window between allocating `Source` and entering the `try` is exactly where an
exception leaks it. It is an error because the leak is unconditional on the
failure path and the fix is mechanical — which is why the spec makes the rewrite
`MachineApplicable`.

## Silencing it

`{@allow(P0505, reason: "...")}` is legitimate when the intervening call is known
not to raise and the code documents that. Otherwise apply `fpcheck fix`.
