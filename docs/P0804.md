# P0804: ignored-io-result

An I/O operation runs while `{$I-}` is in effect and its `IOResult` is never
checked. The failure flag is set, nobody reads it, and execution continues on
error.

## Failing example

```pascal
Assign(F, Path);
{$I-}
Rewrite(F);
{$I+}
WriteLn(F, 'started');   // runs even though Rewrite failed
Close(F);
```

## Fixed example

```pascal
Assign(F, Path);
{$I-}
Rewrite(F);
{$I+}
if IOResult <> 0 then
  raise Exception.CreateFmt('cannot write %s', [Path]);
WriteLn(F, 'started');
Close(F);
```

## Rationale

A failed `Rewrite` leaves the file variable invalid, so the following `WriteLn`
writes nothing while the program reports success — the worst outcome for an agent
debugging by output. It is a warning because the `{$I-}` idiom is sometimes
deliberate. The false-positive risk is on implicit `IOResult` reads the analyzer
does not track.

## Silencing it

`{@allow(P0804, reason: "...")}` is legitimate when the result is deliberately
discarded and a later call's status is checked instead. Otherwise check
`IOResult`, or restore `{$I+}` so the failure raises.
