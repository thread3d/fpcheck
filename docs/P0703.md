# P0703: goto

`goto` and labels are used, producing unstructured control flow. It is a warning
rather than an error because a few patterns — retry loops in generated code,
error paths in legacy units — are genuinely awkward without it.

## Failing example

```pascal
Start := 1;
Retry:
  Val(Copy(S, Start, Length(S)), Result, Code);
  if (Code <> 0) and (Start < Length(S)) then
  begin
    Inc(Start);
    goto Retry;   // jumps back over the loop bookkeeping
  end;
```

## Fixed example

```pascal
Start := 1;
repeat
  Val(Copy(S, Start, Length(S)), Result, Code);
  if Code <> 0 then
    Inc(Start);
until (Code = 0) or (Start > Length(S));
```

## Rationale

The jump duplicates the termination condition in two places, which is how these
loops acquire bugs; a `repeat` states the invariant once. It is a warning because
the rewrite is not always mechanical and a jump to a shared cleanup label can be
the clearest option in a long routine.

## Silencing it

`{@allow(P0703, reason: "...")}` is legitimate for generated code or a shared
cleanup label that a structured rewrite would obscure. Otherwise restructure with
`break`, `continue`, `exit`, or a nested routine.
