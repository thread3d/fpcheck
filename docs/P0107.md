# P0107: result-never-assigned

A function has a path that reaches the end, or an `exit`, without assigning
`Result`. FPC emits the weaker "Function result does not seem to be set"; P0107
is flow-sensitive and names the path.

## Failing example

```pascal
function MaxOf(const A, B: Integer): Integer;
begin
  if A > B then
    Result := A;   // nothing is assigned when A <= B
end;
```

## Fixed example

```pascal
function MaxOf(const A, B: Integer): Integer;
begin
  if A > B then
    Result := A
  else
    Result := B;
end;
```

## Rationale

When `A <= B` the function returns whatever the result slot happened to hold, so
`MaxOf(2, 9)` can print garbage on every run — a correctness bug, not a style
preference. The false-positive risk lies on paths the CFG approximates, such as a
`Result` assigned inside an exception handler treated as optional.

## Silencing it

`{@allow(P0107, reason: "...")}` is legitimate only when the result is set
through a mechanism outside the analyzer's view, such as an assembler block.
Assign `Result` explicitly whenever you can.
