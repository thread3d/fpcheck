# P0803: exception-from-destructor

A path can raise out of `Destroy` or a `finally` cleanup block. An exception
thrown during cleanup replaces the in-flight exception and can skip the rest of
the cleanup.

## Failing example

```pascal
destructor TCache.Destroy;
begin
  FlushToDisk;   // can raise out of the destructor
  FItems.Free;
  inherited Destroy;
end;
```

## Fixed example

```pascal
destructor TCache.Destroy;
begin
  try
    FlushToDisk;
  except
    on E: Exception do
      WriteLn(ErrOutput, 'cache flush failed: ', E.Message);
  end;
  FItems.Free;
  inherited Destroy;
end;
```

## Rationale

If the flush raises, `FItems.Free` and `inherited Destroy` never run, so one
failure leaks the object's own fields while unwinding — and during an existing
exception the original error is discarded. Cleanup code must be total, because it
runs on the worst path by definition.

## Silencing it

`{@allow(P0803, reason: "...")}` is legitimate only when the failure must abort
the cleanup and the code documents that. Guard the call and log instead.
