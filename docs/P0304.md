# P0304: checks-disabled

A `{$R-}`, `{$Q-}` or `{$I-}` directive switches off a runtime check outside an
`{@unsafe}` region. Everything the `dev` profile relies on for faithful failure
behaviour is gone for the rest of the unit.

## Failing example

```pascal
{$R-}   // range checks off for the rest of the unit

function DecodeByte(Value: Integer): Byte;
begin
  Result := Value;   // 300 wraps to 44 without a word
end;
```

## Fixed example

```pascal
function DecodeByte(Value: Integer): Byte;
begin
  if (Value < 0) or (Value > High(Byte)) then
    raise ERangeError.CreateFmt('value out of range: %d', [Value]);
  Result := Value;
end;
```

## Rationale

A disabled check converts a loud failure into a wrong answer, and nothing
downstream can tell the value was ever different. Disabling checks is a
deliberate act, so where it is genuinely needed an `{@unsafe}` region records the
reason. The directive is checked against its region, so there is no path
reasoning to get wrong.

## Silencing it

Wrap the directive in a justified region:
`{@unsafe(reason: "interop with a C library that re-enables its own checks")}`.
The region is what makes the intent auditable, so `{@allow(P0304, ...)}` is not
the intended escape hatch.
