# P0602: mutation-during-iteration

A container is modified — `Add`, `Delete`, `Clear`, `SetLength` — while a
`for..in` or index loop is iterating over it. The iteration state no longer
matches the container.

## Failing example

```pascal
procedure DropEmpty(Items: TStrings);
var
  Item: string;
begin
  for Item in Items do
    if Trim(Item) = '' then
      Items.Delete(Items.IndexOf(Item));   // mutates during iteration
end;
```

## Fixed example

```pascal
procedure DropEmpty(Items: TStrings);
var
  I: Integer;
begin
  for I := Items.Count - 1 downto 0 do
    if Trim(Items[I]) = '' then
      Items.Delete(I);   // deleting behind the cursor is safe
end;
```

## Rationale

Deleting forward shifts the remaining elements, so the enumerator skips the entry
after each removal. Deleting backwards keeps not-yet-visited indices stable. It
is an error because the loop's own bookkeeping is invalidated, not merely because
the result is surprising. The false-positive risk is on snapshot-based
enumerators, where mutation is genuinely safe.

## Silencing it

`{@allow(P0602, reason: "...")}` is legitimate when the enumerator takes a
snapshot. Otherwise collect the changes and apply them after the loop, or iterate
backwards by index.
