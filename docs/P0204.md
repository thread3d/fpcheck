# P0204: duplicate-case-label

Two `case` labels select the same value: the identical label twice, or two
overlapping ranges. FPC rejects this too, but the lint reports it before
compilation, alongside the other findings from the same check.

## Failing example

```pascal
case C of
  'a', 'e', 'i', 'o', 'u': Result := 'vowel';
  'a'..'z': Result := 'lower';   // overlaps the vowels above
else
  Result := 'other';
end;
```

## Fixed example

```pascal
case C of
  'a', 'e', 'i', 'o', 'u': Result := 'vowel';
  'b'..'d', 'f'..'h', 'j'..'n', 'p'..'t', 'v'..'z': Result := 'lower';
  'A'..'Z': Result := 'upper';
else
  Result := 'other';
end;
```

## Rationale

The overlap is a specification bug: the author meant "all lowercase except
vowels", wrote the whole range anyway, and the vowel branch is now unreachable
for `'a'`. There is no meaningful false-positive risk, because one of two
overlapping branches can never run.

## Silencing it

There is no legitimate suppression, so `{@allow(P0204, ...)}` should not appear.
Rewrite the labels so the ranges are disjoint.
