# P0106: could-be-const

A value parameter or local is never reassigned, so it could be declared `const`.
That lets the compiler skip a copy and tells the next reader the binding is not
meant to change.

## Failing example

```pascal
function Describe(const Level: Integer): string;
var
  Prefix: string;
begin
  Prefix := 'level';   // never reassigned
  Result := Format('%s=%d', [Prefix, Level]);
end;
```

## Fixed example

```pascal
function Describe(const Level: Integer): string;
const
  Prefix = 'level';
begin
  Result := Format('%s=%d', [Prefix, Level]);
end;
```

## Rationale

`Prefix` was a constant wearing a variable's clothes: every call re-created the
same string. It is a warning because non-const parameters are legal and
occasionally needed for a mutable copy. The main miss is a value captured by a
nested routine the analyzer does not model.

## Silencing it

`{@allow(P0106, reason: "...")}` is legitimate when the parameter must stay
by-value for ABI or callback reasons. Otherwise add `const`, or promote the
initialised local to a real `const`.
