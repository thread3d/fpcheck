# P0503: use-after-free

A value is used after `Free`, `FreeAndNil`, or a move transferred its ownership.
The related span points at the free or move that invalidated it.

## Failing example

```pascal
begin
  Session := TSession.Create;
  try
    Session.Touch;
  finally
    Session.Free;
  end;
  Session.Touch;   // runs on freed memory
end;
```

## Fixed example

```pascal
begin
  Session := TSession.Create;
  try
    Session.Touch;
    Session.Touch;   // still inside the object's lifetime
  finally
    FreeAndNil(Session);
  end;
end;
```

## Rationale

`Free` releases the object but leaves the variable pointing at the old address,
so the later call runs a method on memory the allocator may already have reused.
The failure is nondeterministic, which makes it expensive to diagnose. The
false-positive risk is on references the analyzer cannot prove are the same value
after a free.

## Silencing it

`{@allow(P0503, reason: "...")}` has no good use here. Move the use inside the
object's lifetime, or use `FreeAndNil` and guard the later use with a nil check.
