# P0501: leak

An `{@owned}` value is not freed or transferred on some path out of the routine,
including paths that leave through an exception. Constructor results are
implicitly owned, so `TFileStream.Create` needs no annotation to be tracked.

## Failing example

```pascal
procedure SaveBuffer(const Path: string; const Buffer: TBytes);
var
  Stream: TFileStream;
begin
  Stream := TFileStream.Create(Path, fmCreate);
  Stream.WriteBuffer(Buffer[0], Length(Buffer));   // may raise
  Stream.Free;                                     // ...and then leaks
end;
```

## Fixed example

```pascal
procedure SaveBuffer(const Path: string; const Buffer: TBytes);
var
  Stream: TFileStream;
begin
  Stream := TFileStream.Create(Path, fmCreate);
  try
    Stream.WriteBuffer(Buffer[0], Length(Buffer));
  finally
    Stream.Free;
  end;
end;
```

## Rationale

A failed write skips `Stream.Free`, leaking a handle and a buffer — the path
`-gh` would only reveal if a test happened to hit it. False positives are on
ownership that genuinely transfers out through a `{@sink}` parameter or a field.

## Silencing it

`{@allow(P0501, reason: "...")}` is legitimate when ownership moves to a
longer-lived owner on every path. Prefer `{@sink}` on the receiving parameter.
