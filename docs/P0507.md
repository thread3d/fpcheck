# P0507: owned-field-not-released

A class has a field marked `{@owned}` that its `Destroy` never frees. Every
instance that is destroyed leaks the field's target.

## Failing example

```pascal
constructor TTokenizer.Create(const Source: string);
begin
  inherited Create;
  FSource := Source;
  FBuffer := TMemoryStream.Create;
end;

destructor TTokenizer.Destroy;
begin
  inherited Destroy;   // FBuffer is never freed
end;
```

## Fixed example

```pascal
destructor TTokenizer.Destroy;
begin
  FBuffer.Free;
  inherited Destroy;
end;
```

## Rationale

The constructor allocates `FBuffer` and the destructor forgets it, so the leak is
proportional to the number of instances created — a slow bleed in a long-running
process. The `{@owned}` annotation is a promise the destructor fails to keep, and
the fix is a single line. False positives occur when the field is released by a
helper the destructor calls, which the analyzer cannot follow.

## Silencing it

`{@allow(P0507, reason: "...")}` is legitimate when the field is released by a
called routine or handed to another owner on every path. If the field does not
own its target, mark it `{@weak}` instead.
