# P0201: non-exhaustive-case

A `case` over an enum, boolean, or subrange has no `else` and does not cover
every value. The unhandled values fall through in silence.

## Failing example

```pascal
function IsLiteral(Kind: TTokenKind): Boolean;
begin
  Result := False;
  case Kind of
    tkNumber, tkString: Result := True;   // tkEOF and tkError unhandled
  end;
end;
```

## Fixed example

```pascal
function IsLiteral(Kind: TTokenKind): Boolean;
begin
  case Kind of
    tkNumber, tkString: Result := True;
    tkIdent, tkSymbol, tkEOF, tkError: Result := False;
  end;
end;
```

## Rationale

A `case` without `else` promises that the listed values are all that occur. When
a new enum member is added — exactly what happens when a lexer learns a token —
the promise breaks silently. Listing every member turns that mistake into a
compile error. The false-positive risk is on members introduced by an `{$IFDEF}`
branch the analyzer evaluated differently.

## Silencing it

`{@allow(P0201, reason: "...")}` is legitimate when surrounding code handles the
remaining values. An explicit `else` you actually intend is usually the honest
fix; do not suppress it because adding branches is tedious.
