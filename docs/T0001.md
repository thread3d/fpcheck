# T0001: failed-test

An FPCUnit test failed. This one comes from the runtime harness: the primary span
is the failing assertion inside the test, and the expected/actual values arrive as
`note` lines.

## Failing example

```pascal
procedure TLexerTests.TestUnterminatedString;
var
  Tok: TToken;
begin
  Tok := Lex('"abc');
  AssertEquals('kind', Ord(tkError), Ord(Tok.Kind));
end;
```

## Fixed example

```pascal
function TLexer.ScanString: TToken;
begin
  Result := ReadUntilQuote;
  if Result.Kind = tkString then
    Result := TToken.Error('unterminated string');   // input ended first
end;
```

## Rationale

The test is right and the lexer is wrong: `ScanString` consumed to end of input
and reported an ordinary string, so the failure points at real behaviour rather
than a brittle assertion. The harness renders it with expected and actual values
plus a symbolized stack, which is what lets an agent fix the code under test
without re-running by hand. There is no false-positive risk when the test is the
specification.

## Silencing it

Do not suppress T0001: a failing test means the code and the specification
disagree. Fix the code, or correct the assertion if the specification itself
changed.
