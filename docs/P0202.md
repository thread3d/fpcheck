# P0202: wildcard-else-on-enum

A `case` marked `{@exhaustive}` still has an `else`. That fallback swallows
exactly the case the annotation exists to catch: a newly added enum member taking
the default path instead of failing to compile.

## Failing example

```pascal
{@exhaustive}
case Kind of
  tkIdent: Result := 'identifier';
  tkNumber, tkString: Result := 'literal';
else
  Result := 'other';   // hides any member added later
end;
```

## Fixed example

```pascal
{@exhaustive}
case Kind of
  tkIdent: Result := 'identifier';
  tkNumber, tkString: Result := 'literal';
  tkSymbol, tkEOF, tkError: Result := 'other';
end;
```

## Rationale

`{@exhaustive}` is a maintenance contract: add an enum member and the compiler
lists every `case` that must be updated. The `else` voids it, because the new
member quietly becomes "other". The lint is `allow` by default precisely because
the annotation is opt-in, so the false-positive risk is essentially nil.

## Silencing it

Drop `{@exhaustive}` if the fallback is intended, or write
`{@allow(P0202, reason: "...")}` when the fallback is deliberate and the
annotation is still wanted for the other members.
