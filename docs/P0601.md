# P0601: var-param-aliasing

The same variable is passed to two `var`/`out` parameters, or to a `var`
parameter and a `const` parameter whose callee mutates through it. The callee's
writes are then visible through both names at once.

## Failing example

```pascal
procedure Fix;
var
  Value: Integer;
begin
  Value := 7;
  SwapValues(Value, Value);   // one variable, two var parameters
  WriteLn(Value);
end;
```

## Fixed example

```pascal
procedure Fix;
var
  Value, Other: Integer;
begin
  Value := 7;
  Other := Value;
  SwapValues(Value, Other);   // each argument is a distinct variable
  WriteLn(Value);
end;
```

## Rationale

`SwapValues(Value, Value)` does not sort anything: writing `A` and writing `B`
are the same store, so the result depends on the callee's internal order. The
program compiles and runs, which is why the bug survives. The false-positive risk
is on aliasing the analyzer cannot prove through a pointer.

## Silencing it

`{@allow(P0601, reason: "...")}` is legitimate only when the callee handles the
aliased case, which should be documented at the callee. Usually copy one argument.
