# P0306: float-equality

Floating-point operands are compared with `=` or `<>`. Binary floating point
cannot represent most decimal fractions exactly, so a mathematically equal pair
often compares unequal.

## Failing example

```pascal
function IsBalanced(const Total: Double): Boolean;
begin
  Result := Total = 0.0;   // ten additions of 0.1 do not sum to exactly 1.0
end;
```

## Fixed example

```pascal
function IsBalanced(const Total: Double): Boolean;
begin
  Result := Abs(Total) < 1e-9;   // states the tolerance the code means
end;
```

## Rationale

Rounding error accumulates through arithmetic, so the exact comparison fails on
values that are equal for every practical purpose. It is a warning because
sentinel comparisons and copies are legitimate, and because choosing the right
epsilon is a domain decision the analyzer cannot make. False positives are
therefore expected.

## Silencing it

`{@allow(P0306, reason: "...")}` is legitimate for a sentinel comparison or a
value that is only ever copied, never computed. Prefer an explicit epsilon
wherever the operands result from arithmetic.
