# P0506: dangling-after-free

A field or global is freed with `Free` and left holding the old address, so a
later read through that reference touches freed memory. `FreeAndNil` is the
suggested fix.

## Failing example

```pascal
procedure TService.Invalidate;
begin
  FCache.Free;   // FCache still points at freed memory
end;

function TService.Cache: TObject;
begin
  Result := FCache;   // nil-checking callers get a false answer
end;
```

## Fixed example

```pascal
procedure TService.Invalidate;
begin
  FreeAndNil(FCache);   // the reference becomes nil
end;

function TService.Cache: TObject;
begin
  Result := FCache;     // nil until it is rebuilt
end;
```

## Rationale

`Free` releases the object but not the reference, so `Cache` keeps returning a
non-nil pointer to nothing and a caller's nil check lies. It is a warning because
the pattern only harms if something reads the field later; the false-positive
risk is on code that reassigns it immediately.

## Silencing it

`{@allow(P0506, reason: "...")}` is legitimate when the field is unconditionally
reassigned before any read. Otherwise `FreeAndNil` removes the window entirely.
