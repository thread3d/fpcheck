# P0302: signed-unsigned-mix

A comparison or arithmetic operation mixes signed and unsigned operands of
unequal range. Pascal promotes both sides to a common type, and the signed value
is reinterpreted in the unsigned domain.

## Failing example

```pascal
function IsBefore(const Offset: Integer; const Limit: Cardinal): Boolean;
begin
  Result := Offset < Limit;   // -1 becomes $FFFFFFFF here
end;
```

## Fixed example

```pascal
function IsBefore(const Offset: Integer; const Limit: Cardinal): Boolean;
begin
  Result := (Offset >= 0) and (Cardinal(Offset) < Limit);
end;
```

## Rationale

Asking whether `-1` is before `10` answers `False`, because the comparison
happens in unsigned space. FPC only hints about the 64-bit promotion, so the
wrong answer reaches the program. The risk is on operands already proven
non-negative, which the flow analysis may not see.

## Silencing it

`{@allow(P0302, reason: "...")}` is legitimate when one operand's domain is
already constrained above and that is documented nearby. Otherwise convert both
sides to a common signed type.
