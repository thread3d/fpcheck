# P0903: global-mutable-state

A mutable unit-level variable is reachable from more than one thread entry point.
Two threads can read and write it with no ordering, so the value one sees depends
on timing.

## Failing example

```pascal
var
  RequestCount: Integer;   // mutated from every worker thread

procedure RecordRequest;
begin
  Inc(RequestCount);   // unsynchronised read-modify-write
end;
```

## Fixed example

```pascal
var
  RequestCount: Integer;   // only ever changed atomically

procedure RecordRequest;
begin
  InterlockedIncrement(RequestCount);   // one atomic operation
end;
```

## Rationale

`Inc` is a load, an add, and a store; two threads interleaving those three steps
lose increments, so the counter drifts low in exactly the runs that matter. It is
`allow` by default because single-threaded programs are correct without any of
this, and false positives are expected in programs that never create a thread.

## Silencing it

`{@allow(P0903, reason: "...")}` is legitimate when the program is provably
single-threaded or the variable is only read after the workers have joined.
Otherwise use an atomic operation or protect the access with a lock.
