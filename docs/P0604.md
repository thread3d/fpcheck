# P0604: reference-to-local-escapes

The address of a local (`@local`, `Addr(local)`, or a `var`/`const` parameter's
address) is stored into or returned to a location that outlives the routine. The
pointer aims at a stack frame about to be reused.

## Failing example

```pascal
procedure RecordError;
var
  Buffer: array[0..63] of Char;
begin
  StrPCopy(Buffer, 'disk full');
  GLastError := Buffer;   // address of a local escapes
end;
```

## Fixed example

```pascal
var
  GLastError: array[0..63] of Char;

procedure RecordError;
begin
  StrPCopy(GLastError, 'disk full');   // storage outlives the routine
end;
```

## Rationale

`Buffer` ceases to exist when `RecordError` returns, and the next call in that
frame overwrites it — so the program may print the right text, garbage, or
something that looks valid. It is an error because a pointer to a dead local is
never safe. The false-positive risk is on addresses used only within the
routine's lifetime, which the analyzer cannot always distinguish.

## Silencing it

`{@allow(P0604, reason: "...")}` is legitimate when the receiving location is
consumed before the routine returns, which the code should make obvious.
Durable fixes are to copy the value, move the storage to unit scope, or
heap-allocate it.
