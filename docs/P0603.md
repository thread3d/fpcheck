# P0603: interior-reference-invalidated

A pointer, `var` alias, or `with` target pointing into a dynamic array, string,
or container element is held across an operation that can reallocate it —
`SetLength`, `Add`, `Insert`, a string append.

## Failing example

```pascal
First := @Values[0];                    // points into the array
SetLength(Values, Length(Values) + 1);  // may reallocate
Values[High(Values)] := Extra;
WriteLn('first was ', First^);          // stale address
```

## Fixed example

```pascal
First := Values[0];                     // copy the value, not the address
SetLength(Values, Length(Values) + 1);
Values[High(Values)] := Extra;
WriteLn('first was ', First);
```

## Rationale

`SetLength` may move the array to a new block, leaving the pointer aimed at freed
memory — the later read is a use-after-free that often returns a plausible old
value. It is an error because the invalidation is deterministic on the
reallocating path. False positives come from operations flagged as reallocating
that cannot actually move this buffer.

## Silencing it

`{@allow(P0603, reason: "...")}` is legitimate when the capacity is known to be
sufficient so the call cannot reallocate. Otherwise re-take the reference after
the call, or copy the element out first.
