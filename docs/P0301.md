# P0301: implicit-narrowing

A value is assigned or passed into a smaller type without an explicit
conversion: `Int64` into `Integer`, `Integer` into `Byte`. The narrowing is
silent unless range checking happens to be on.

## Failing example

```pascal
procedure SetPixelCount(const Count: Int64);
var
  Pixels: Integer;
begin
  Pixels := Count;   // Int64 -> Integer, truncated silently
end;
```

## Fixed example

```pascal
procedure SetPixelCount(const Count: Int64);
var
  Pixels: Integer;
begin
  if (Count < Low(Integer)) or (Count > High(Integer)) then
    raise ERangeError.CreateFmt('pixel count out of range: %d', [Count]);
  Pixels := Integer(Count);
end;
```

## Rationale

`5000000000` keeps only its low 32 bits, so the program reports a
plausible-but-wrong pixel count instead of failing. Range checking catches it in
`dev` builds, but that is exactly what release profiles may disable, so the
static diagnostic is the signal that survives. The risk is on values the analyzer
cannot bound, so it reports the conversion itself rather than a proven overflow.

## Silencing it

`{@allow(P0301, reason: "...")}` is legitimate when the value is already proven
in range and the conversion documents that. Prefer an explicit `{to}(x)` cast or
a checked helper.
