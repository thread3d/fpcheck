# P0401: nil-dereference

A value that may be `nil` is dereferenced without any path proving it non-nil.
The lint is flow-sensitive: an `if Config <> nil then` guard narrows the value.

## Failing example

```pascal
procedure PrintHost(const Path: string);
var
  Config: TConfig;
begin
  Config := LoadConfig(Path);   // returns nil when the file is absent
  WriteLn(Config.Host);         // dereferenced without a check
end;
```

## Fixed example

```pascal
procedure PrintHost(const Path: string);
var
  Config: TConfig;
begin
  Config := LoadConfig(Path);
  if Config = nil then
  begin
    WriteLn('(no config)');
    exit;
  end;
  WriteLn(Config.Host);
end;
```

## Rationale

The call dies at the first field access, far from the routine that returned
`nil`. The false-positive risk is inherent to flow analysis: a guard hidden
behind `Assert`, or inside a called routine, is missed — so it errs toward
silence when a path is unclear.

## Silencing it

`{@allow(P0401, reason: "...")}` is legitimate when the caller contract
guarantees non-nil, preferably stated with a `{@nonnull}` annotation.
