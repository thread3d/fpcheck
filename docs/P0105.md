# P0105: shadowed-name

A local declaration reuses a name that already exists in an outer scope — a
parameter, a field, or a unit-level symbol. Inside the routine the outer binding
becomes invisible, usually without the author noticing.

## Failing example

```pascal
function TTokenizer.NextToken: string;
var
  FPosition: Integer;   // shadows the field of the same name
begin
  FPosition := FPosition + 1;
  Result := Format('token-%d', [FPosition]);
end;
```

## Fixed example

```pascal
function TTokenizer.NextToken: string;
var
  Position: Integer;
begin
  FPosition := FPosition + 1;
  Position := FPosition;
  Result := Format('token-%d', [Position]);
end;
```

## Rationale

The method appears to advance the tokenizer's cursor but mutates a throwaway
local, so the real field never moves and the bug surfaces only as wrong output
later. Shadowing is legal Pascal, which is why it is worth a warning rather than
an error; the false-positive risk is low.

## Silencing it

`{@allow(P0105, reason: "...")}` is legitimate when the reused name is
intentional and the outer binding is not needed in that scope. Renaming the
inner declaration is almost always the better fix.
