# P0102: unused-result

A function whose result must be consumed was called and the result dropped. The
spec applies this to `{@must_use}` functions and, by default, to project-declared
functions returning `Boolean` or an error code.

## Failing example

```pascal
procedure LoadPort(const Text: string);
var
  Port: Integer;
begin
  TryParsePort(Text, Port);   // the Boolean result is discarded
  WriteLn('listening on ', Port);
end;
```

## Fixed example

```pascal
procedure LoadPort(const Text: string);
var
  Port: Integer;
begin
  if not TryParsePort(Text, Port) then
    raise Exception.CreateFmt('invalid port: %s', [Text]);
  WriteLn('listening on ', Port);
end;
```

## Rationale

The discarded result is almost always the failure signal, and the `out`
parameter is then left holding whatever it had before — printed here as if it
were a real port. This is the classic ignored-error bug in a language with no `?`
operator, and the lint is not flow-sensitive, so its false-positive risk is low.

## Silencing it

`{@allow(P0102, reason: "...")}` is legitimate when the call exists purely for
its side effect. Prefer making that explicit by assigning the result to a local,
and never suppress it to hide an unchecked error path.
