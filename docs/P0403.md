# P0403: redundant-nil-check

A value is tested for `nil` after something earlier in the same routine already
proved it non-nil. The second check can never take the nil branch.

## Failing example

```pascal
procedure Emit(const Node: TNode);
begin
  if Node = nil then
    exit;
  WriteLn(Node.Name);
  if Node <> nil then   // already proven non-nil above
    WriteLn('emitted ', Node.Name);
end;
```

## Fixed example

```pascal
procedure Emit(const Node: TNode);
begin
  if Node = nil then
    exit;
  WriteLn(Node.Name);
  WriteLn('emitted ', Node.Name);
end;
```

## Rationale

A redundant guard is a small lie: it tells the next reader that `Node` might be
nil here, when the function has already established otherwise. Agents add these
defensively, and each one inflates the set of states a reader must consider. It
is a warning because the code is harmless and occasionally kept as protection
against a future edit.

## Silencing it

`{@allow(P0403, reason: "...")}` is legitimate when the check is deliberately
kept as a belt-and-braces guard. Otherwise delete it, or delete the earlier check
if this is the one you meant to keep.
