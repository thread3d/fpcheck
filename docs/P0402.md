# P0402: nullable-to-nonnull

A value declared `{@nullable}` is passed or assigned to a target declared
`{@nonnull}`. The annotations form a contract, and this call breaks it.

## Failing example

```pascal
{@nullable}
function FindSession(const Id: string): TSession;

procedure Use({@nonnull} Session: TSession);

procedure Run(const Id: string);
begin
  Use(FindSession(Id));   // nullable result where nil is forbidden
end;
```

## Fixed example

```pascal
procedure Run(const Id: string);
var
  Session: TSession;
begin
  Session := FindSession(Id);
  if Session = nil then
    exit;
  Use(Session);   // narrowed to non-nil before the call
end;
```

## Rationale

The annotations disagree, so one is wrong: either `Use` must accept `nil` or
`Run` must handle the missing session. Pointing at the crossing forces that
decision at the boundary instead of at the crash site. False positives come only
from flow the analyzer cannot see, such as a nil check the annotation forbids.

## Silencing it

`{@allow(P0402, reason: "...")}` is legitimate only when the value is proven
non-nil just outside the analyzed scope. Usually change one annotation instead.
