# P0101: uninitialized-use

`Total` is read before anything assigns it. FPC only hints about the easy cases;
P0101 is flow-sensitive across branches, loops and exception paths.

## Failing example

```pascal
function Sum(const Values: array of Integer): Integer;
var
  I, Total: Integer;
begin
  for I := Low(Values) to High(Values) do
    Total := Total + Values[I];   // Total is read before it is ever set
  Result := Total;
end;
```

## Fixed example

```pascal
function Sum(const Values: array of Integer): Integer;
var
  I, Total: Integer;
begin
  Total := 0;
  for I := Low(Values) to High(Values) do
    Total := Total + Values[I];
  Result := Total;
end;
```

## Rationale

The stack slot holds whatever the previous frame left there, so the function
returns a random sum — a genuine bug class rather than a style issue. Because it
is flow-sensitive, the false-positive risk sits on paths the analyzer models
imprecisely, such as assignment inside a nested routine; it stays silent when it
cannot prove a path is unassigned.

## Silencing it

`{@allow(P0101, reason: "...")}` is legitimate only when the value is
initialised in a way the analyzer cannot see, such as an imported routine filling
a buffer by reference. Never use it to keep a real read-before-write.
