# P0701: unsafe-outside-unsafe

An unsafe construct is used outside an `{@unsafe}` region: address-of, pointer
arithmetic, untyped `var`/`const` parameters, `absolute`, size-changing hard
casts, `Move`/`FillChar` on managed types, inline `asm`, and the `{$R-}` family.

## Failing example

```pascal
Raw := PByte(@Header);          // address-of
Inc(Raw, SizeOf(THeader) - 1);  // pointer arithmetic
Raw^ := 0;                      // writes past the field it meant to clear
```

## Fixed example

```pascal
Header.Flags := 0;              // write the field directly
```

## Rationale

The pointer walk silently depends on the record's exact layout: add a field or
change the packing and `Raw` writes the wrong bytes, or past the record
entirely. The escape hatch is not a suppression but a declared region,
`{@unsafe(reason: "...")}`, which keeps the reason attached to the code. The
construct list is syntactic, so false positives are low.

## Silencing it

`{@allow(P0701, reason: "...")}` is not the intended escape hatch — the region
is. Write `{@unsafe(reason: "the wire format fixes this layout")}` around the
code, or rewrite it to use typed field access.
