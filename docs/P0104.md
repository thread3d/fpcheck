# P0104: unreachable-code

A statement can never execute because control flow always leaves first: after
`exit`, `raise`, `Halt`, or an infinite loop. The CFG also catches this after
`break` and `continue`.

## Failing example

```pascal
procedure Fail(const Message: string);
begin
  raise Exception.Create(Message);
  WriteLn('unreachable: ', Message);
end;
```

## Fixed example

```pascal
procedure Fail(const Message: string);
begin
  raise Exception.Create(Message);
end;
```

## Rationale

Dead code is a lie about behaviour: an agent that turns the `raise` into a log
call will believe the next line still runs, and the compiler keeps the stale
statement. It is a warning because the unreachable line is occasionally a
deliberate placeholder. The false-positive risk is on loops the CFG cannot prove
terminate.

## Silencing it

`{@allow(P0104, reason: "...")}` is legitimate when a generation or preprocessor
pass will later make the statement reachable. Otherwise delete it, or remove the
call that ends the path early.
